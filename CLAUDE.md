# Snow Dream (Pegasus)

Godot 4.7 .NET (C# only, no GDScript), desktop. Hobby project: keep it simple (YAGNI, KISS), clean modules, no backward compatibility.

## Layout

Folders follow the architecture layers. A layer only uses layers below it; folders in the same layer may use each other (the day HUD in `ui/hud` shows `day/` activities and shops, and day places show that HUD).

| Layer | Folders |
|---|---|
| Scenes | `day/`, `night/`, `puzzles/`, `ui/` |
| Shared gameplay | `world/` (player, camera, interactables), `conditions/`, `dialogue/` |
| Core services (autoloads) | `core/` (GameState, SceneRouter, SaveService, AudioService, Settings) |
| Content (data, not code) | `content/` (Resource `.tres` files, `.yarn` scripts) |

Flow: the main scene is `ui/title` (Continue unless the save has ended, New game with a confirm before it replaces an unfinished save, Settings, Quit); `DayCycle.Enter` goes into the world from the state; `core/DayCycle` runs bed → 3 AM night → morning and saves at both; `core/SceneRouter` (autoload) changes scenes behind a fade and pauses the tree meanwhile. A scene's `_Ready` runs in the dark, so anything it says on arrival goes through `SceneRouter.WhenIdle`. `ui/Toast` (autoload) shows one line of feedback; lines queue and wait out fades.

Story beats (`content/dialogue/story.yarn`): the apartment plays the intro and two control tips on the first afternoon, the snow area plays a first-night line and one Warmth tip, and the morning after the first whiteout gets one line pointing at winter gear. That is all the guidance the game gives. Lighting the stove in Kissa Mori jumps to the `Ending` node, whose `<<end_game "caption">>` calls `DayCycle.Finish`: it sets `ended`, saves and shows `ui/ending/end_card.tscn` (its button goes back to the title); `DayCycle.Enter` shows the card for an ended save, so there is no play after the ending. Flags the code itself reads live in `core/state/Flags.cs`.

Dialogue: Yarn Spinner for Godot is vendored in `addons/YarnSpinner-Godot` (MIT, v0.3.23, upstream commit b0abe88); do not edit it. Scripts live in `content/dialogue/*.yarn` (one `dialogue.yarnproject`). `ui/dialogue/conversation.tscn` (autoload `Conversation`) runs them through our own `ui/dialogue/DialogueBox`. Start one with `Conversation.Start("Node")` (pass a callback to run something after it) or an `world/npc/npc.tscn` with a `CharacterProfile` (`content/characters/*.tres`; register it in the Conversation scene's Characters list). Yarn reads and writes game state only through `dialogue/YarnBindings.cs` (`met("...")`, `<<stat>>`, `<<give>>`, `<<flag>>`, `<<bond>>`, `<<wake_up "why">>` to end the night, `<<end_game "caption">>` to end the slice...); never keep game facts in Yarn `$variables`. Choices tagged `#needs:guts>=2` stay visible but locked (write the condition with no spaces, and no `<`, `$` or `#`, e.g. `#needs:guts>=2|item:flashlight`); `<<if>>` on a choice hides it instead. A line picks the speaker's portrait with `#mood:smile` or `#mood:worried` (untagged is neutral); tag parsing is `dialogue/LineTags`. Every choice group needs at least one choice the player can always take: if all are locked or hidden the box shows them and then ends the conversation (the vendored runner cannot fall through). Input ownership: `core/InputLock` (dialogue, fades, later menus and puzzles).

Characters: 2D billboards (`Sprite3D`, pixel size 0.003125 for the 256×512 sprites, centre 0.7625 m up so the feet on row 500 touch the ground), art in `content/characters/` (style guide `art/style/README.md`). The player shows a `world/player/SpriteSet` per outfit (`player_summer.tres`, `player_coat.tres`: front, back, side drawn facing right and flipped for left), faces the way he walks and bobs once a step; `core/state/Wardrobe` picks the coat at night once he owns `down_coat`. People stand facing front with their `CharacterProfile.Sprite`; a profile has a neutral `Portrait` plus `PortraitSmile` and `PortraitWorried` (a missing mood shows neutral).

Day places: to add one, make a `LocationData` in `content/locations/*.tres`, a scene whose root script is `day/DayLocation` (or derives from it) with that data, an exit, an instance of `ui/hud/day_hud.tscn` set as its `Hud`, and a `world/bounds/Bounds` node around the walkable area, then add the `.tres` to the `Locations` list in `day/city_map/city_map.tscn`. Every scene with open edges needs a `Bounds` node. Activities: an `ActivityData` in `content/activities/*.tres` (title, verb, gains), offered by a `day/ActivitySpot` in the scene and listed in the place's `LocationData.Activities` for the map. Doing one spends a slot behind a fade (`SceneRouter.Interlude`). A hangout is an activity with `With` (a CharacterProfile), `Bond = 1` and a `YarnScene` prefix: it plays `{YarnScene}1` to `3` by the bond level it raises, then `{YarnScene}Again`; the activity adds the bond afterwards, so hangout scripts don't `<<bond>>`. Place the person as `world/npc/npc.tscn` with no `YarnNode` (Talk stays off) and an `ActivitySpot` at the same spot. Stats and bonds cap at 3 (`GameState.MaxStat`, `MaxBond`).

Items: an `ItemData` in `content/items/{id}.tres` (the file name is the id; look it up with `world/items/Items.Get(id)`). An item with `Warmth > 0` is night gear: `core/state/Warmth` adds it to the base and the Fitness bonus. Give one from Yarn with `<<give id>>`, or sell it: a `day/ShopData` in `content/shops/*.tres` lists the stock, a `day/ShopSpot` in the scene opens it, and the place's `LocationData.Shops` lists it for the map. Browsing is free; buying goes through `GameState.TryBuy`. The Tab menu (`ui/menu`, autoload `Menu`) shows status, items and the notebook; it opens only when the input lock is free and a player is in the scene, and pauses the tree while open.

Night: `night/snow_area` is the one snow area, a grey-box mirror of the neighbourhood. Warmth starts at `Items.MaxWarmth()` and drains at `Warmth.DrainPerSecond` (tune `Warmth.BaseSeconds`) only while `InputLock.IsFree`, so thinking (dialogue, menu, close-ups) is free and walking costs. At zero, or at the home door, `DayCycle.WakeUp` ends the night; nothing is lost but the rest of it. The night HUD (`ui/hud/night_hud.tscn`) shows only Warmth (frost creeps in from the screen edges below half), the bike light (F, once he owns `flashlight`) and the interact prompt. The camera looks north from the south of the player, so keep anything south of a walkable path under about 3 m or it hides him; where that can't hold (the railway bridge), a `world/Cutaway` area fades the listed meshes while he is inside; keep the area off any faded mesh he can bump into from outside it, or it becomes an invisible wall.

Gates: any `Interactable` or `Hotspot` takes `Requires` (a condition) and `LockedYarnNode`, which plays instead until the condition holds. The locked line may hint at the kind of help (more nerve, a real light, someone who reads the old script) but never names items or flags. Most gates take two keys, a stat or a friend's help (`guts >= 2 | item:flashlight`). To block the way, use `world/Gate` (a StaticBody3D with `OpenWhen`): solid and visible while closed, with a child `Examine` for the locked line; once open it hides, stops colliding and turns that off. Night route: lanterns open the hall (stone tablet, Knowledge or Aoi's notes); the underpass (Guts or the flashlight) leads to the arcade and Kissa Mori, the room-escape (`puzzles/cafe`): its stove lock answers the tablet's rule and the shrine's matches light it, so it needs both branches. Sitting down to sleep there ends the night; lighting the stove sets `cafe_fire_lit` for the ending.

Puzzles: each puzzle is its own scene in `puzzles/<name>/` whose root derives from `puzzles/Puzzle` (`Title`, `SolvedFlag`). Each child Control is one view (a wall, named for the title bar), holding `puzzles/Hotspot` buttons (a tag `Label` and a `YarnNode` for what he sees) over placeholder art. The `CloseUp` autoload (`puzzles/close_up/`) frames it as in the mockup: title, arrows between views, his items along the bottom (pick one, then a hotspot, or another item to combine them by `puzzles/rules/Recipes`; the result's line is the Yarn node `Made_{id}`) and Warmth paused. It holds the input lock and closes if the scene changes. Esc calls `Puzzle.StepBack()`, which by default steps back and drops partial progress (a locked room overrides it, as the coffee shop does); `Opened()` can say something on the way in. Steps that last (a lock opened, an item placed) are flags or items; only fiddly state like dials resets. The solved flag is saved, which the 3D world shows with `world/ShowIf` (visual only, no collision). Open a puzzle from the world with a `puzzles/PuzzleSpot`. If it has rules to get wrong (an order, a combination), put them in a pure class under `puzzles/rules/` (linked into `tests/`) and test the solution and a wrong try. Every puzzle's answer must be findable in the night world alone (day clues only help; the way in may still be a gate that takes a stat or a friend, like the tablet's), with no fail penalty. Examine text goes through the dialogue box (`world/interaction/Examine` in 3D, `Hotspot.YarnNode` in close-ups), and reading a clue sets a `clue_*` flag for the notebook.

Notebook: every `<<flag clue_*>>` needs an entry at `content/clues/{flag}.tres` (`ui/notebook/ClueData`: `Title` like "Shrine · Lanterns", `Text`, `Order` to group by place: shrine 10s, underpass 20s, Kissa Mori 30s, and `ByDay` for things heard from friends). An entry records what he saw or heard and stands alone (quote the words he needs); no objectives, next steps or hints. The menu's notebook column lists the entries he has, and the first time a clue flag is set a "Notebook updated" toast follows the conversation.

Audio: `core/AudioService` (autoload) plays the cues listed in its `Music` and `Sfx` enums from `content/audio/music/{snake_case}.ogg` (looped, crossfaded) and `content/audio/sfx/{snake_case}.ogg`; a cue with no file yet is skipped (a warning in debug builds), so add sound by dropping in the file. Each scene root names its music (`Music` export on `DayLocation`, `CityMap`, `SnowArea`, `Title`, `EndCard`; a `Puzzle` with `Music` set plays it while open and `None` keeps the world's). Buses: Master, Music, SFX. Every button clicks by itself. `core/Settings` keeps volumes and fullscreen in `user://settings.cfg`, apart from the save, applied at boot; `ui/settings/settings_panel.tscn` edits them on the title screen and the pause page.

Esc backs out of whatever is on top (a panel, the map, a close-up, the menu); in the open world it opens the menu on its System page (pause: resume, settings, quit to title, which warns that progress since he last slept is lost; there is no save-anywhere). Tab opens the status page; inside the menu Esc on status goes to System and Tab on System goes back. In every menu E, Space or Enter presses the focused button (`ui_accept`) and WASD or the arrows move focus.

UI: all styling lives in `ui/theme.tres`, the project's default theme. Give nodes a type variation from it (`NavyPanel`, `CreamPanel`, `TagOrange`, `KeyCap`, `PrimaryButton`, `ChoiceButton`...) rather than colour or stylebox overrides, so the A6 UI kit is a theme swap. Build new screens as `.tscn` scenes.

Also: `sandbox/` grey-box test scene, `dev/` dev-only helpers, `tests/` xUnit tests for pure logic, plus `tests/ContentTests`, which reads the content as text: conditions parse and name real items, every Yarn node a scene or script plays exists, every clue flag has a notebook entry and the reverse, only known characters speak and every `#mood:` is a known mood (Yarn reads `Text:` at the start of a line as a speaker, so keep colons out of narration).

State and rules: `core/state/` (GameState, SaveData), `conditions/`, `puzzles/rules/` and `dialogue/LineTags.cs` are pure C# with no Godot types, so `tests/` can compile them directly. Keep Godot code out of those folders. Read and change state through `Game.State` (`core/Game.cs`); gates use condition strings such as `"guts >= 2 | item:flashlight"` (`conditions/ConditionParser.cs` has the grammar).

Conventions: snake_case folders and scene files, PascalCase C# files, namespace `Pegasus.<Module>`. Game state is plain C# data kept apart from nodes; scenes rebuild from it on load. Grey-box art and placeholder sound until real assets land.

## Commands

- Build: `dotnet build`
- Tests: `dotnet test`
- Run headless: `godot --headless --quit-after 120 [res://scene.tscn]` (main scene is the title; add `-- --new-game` to start fresh or `-- --continue` to load the save, skipping it)
- Screenshot: `[SHOT_SIZE=1600x700] scripts/shot.sh /tmp/out.png [res://scene.tscn] [frames] [extra dev args, e.g. --hold=move_right@1-40 --tap=interact@60]` (see `dev/DevDriver.cs`; `--state=/abs/state.json` starts from a save-format fixture, and each shot prints the player position and state; frames keep counting while the tree is paused; `--open=res://puzzles/x/x.tscn` opens a puzzle on frame 5 (name a gameplay scene too; it exits 1 if the open is blocked) and `--click=X,Y@F` clicks at 1280x720 viewport coordinates; `--at=X,Z` puts the player there on frame 2 (same: exits 1 with no player); `--key=Escape@F` presses a physical key; `--talk[=F]` advances conversations by itself, taking the first open choice, until frame F)
- Smoke route (on demand, not CI): `scripts/smoke.sh` plays Kissa Mori's stove to the end card and reloads an ended save from `tests/smoke/*.json` fixtures, asserting the final scene and `ended` flag (the dev driver now prints `Scene:` too). Move its click positions if the close-up layout changes.
- After adding new assets or editing `.yarn` files, import: `godot --headless --import` (runs use the compiled Yarn until then; on a fresh checkout run it twice, the first pass can fail on new files)
